# Расширенный тест (extended) — описание

Документ описывает **расширенный** тест скорости Strata и его связь с **ориг.** тестом.
Оригинальный тест остаётся без изменений: `strata_bench.py` (suite 1). Расширенный —
это надстройка над ним, только с расширенной сеткой длин промпта.

## Названия

- **ориг. тест** — `strata_bench.py` (suite 1): chat + 4K + 16K + agent (+ опции `--long` 32K, `--clients N`).
- **Расширенный тест** — `strata_bench_extended.py`: тот же метод, сетка из 9 длин
  промпта (+ параллельный режим `--parallel N`, схема extended-3).

## Что измеряет расширенный тест

Прогон промптов девяти длин (K = 1024 токенов):

```
4K  16K  32K  64K  86K  128K  150K  184K  250K
4096 16384 32768 65536 88064 131072 153600 188416 256000
```

На каждую длину — 3 свежих запроса, медиана с диапазоном. Метрики на каждую длину:

- **Prompt tok/s** — скорость чтения промпта (свои тайминги движка, `prompt_per_second`);
- **TTFT** (time to first token) — время до первого токена, измеряется клиентом по HTTP;
- **Decode tok/s** — скорость генерации на ответных токенах (`predicted_per_second`).

## Ответные токены: 24 (база — алгоритм ориг. теста)

Ориг. тест для prompt-замеров использует `LONG_MAX_TOKENS = 24` (см. `tools/strata_bench.py:57`):
короткий ответ, чтобы в метрику не вмешивался decode и `prompt tok/s` оставался чистым.
Расширенный тест берёт те же **24** ответных токена на каждую длину — по той же причине:
сетка длин измеряет именно prefill, decode здесь вторичен. Скорость decode берётся из
коротких ответов (24 токена) и служит ориентиром, а не основной метрикой длинной сетки.

## Метод (общий с ориг. тестом)

- **Калибровка слов→токенов**: два калибровочных запроса (200 и 800 слов) дают наклон
  `tokens_per_word`, чтобы фиксированная часть шаблона не сдвигала размер промпта.
- **Промпт** = сгенерированный список слов нужного размера + уникальный тег в начале
  (`[ext <run>-<tokens>-p-<nonce>]`), поэтому кэш диалога не может помочь свежему промпту.
- **Свежие промпты**: каждый прогон — новый промпт, без повторов внутри сервера.
- **Прогрев**: один chat и один 1K-промпт отбрасываются до замеров.
- **Thinking off**, temperature 0 — ответы короткие и сопоставимые.

## Требования

- **Контекст сервера ≥ 262144**: самый большой промпт 250K = 256000 токенов + 24 ответных
  должен влезать в контекст. При меньшем контексте длинные размеры помечаются `skipped`.
- Все батники запуска в этом проекте рассчитаны на **262144** (проверено: main, -2gpu,
  -2gpu-p2/p3/p4, -3gpu, -3090-vision, -3090-novision).

## Как запускать

По уже запущенному серверу:

```
python tools/strata_bench_extended.py --url http://127.0.0.1:8081 --api-key <ключ>
```

Самостоятельно (поднимает сервер по конфигу, гоняет, останавливает его):

```
python tools/strata_bench_extended.py --config strata-<model>.json --port 8082
```

Опции: `--runs N` (прогонов на длину, по умолчанию 3), `--out DIR` (куда класть папку),
`--ready-timeout S`, `--parallel N` (параллельный режим, см. ниже; 0 — выключен),
`--parallel-runs R` (раундов на длину в параллельном режиме, по умолчанию 2),
`--gpus-used N` (сколько из карт ПК реально использует сервер).

Важно про `--gpus-used`: при запуске через `--url` тест не видит параметров запуска сервера и
именует папку по картам, которые показывает драйвер. Если сервер поднят не на всех картах
(например, в конфиге `"gpu": [0]` на ПК с двумя), передай `--gpus-used 1` — тогда папка и отчёт
назовутся `2x1x-rtx-3090` (хост × использовано), а `results.json` получит `gpus_used`.
То же в `strata_bench.py` и `strata_bench_slots.py`. Если тест уже отработан без флага —
проставь `machine.gpus_used` в `results.json` вручную и поправь заголовок README.

## Куда пишется результат

`bench/results/<date>-extended-<gpu>-<model>/` — `../README.md` в формате
`docs/COMMUNITY_BENCHMARKS.md` и `results.json` (каждый запрос). Домашние папки, имена
пользователя/хоста, IP и API-ключ заменяются плейсхолдерами до записи.

## Параллельный режим (`--parallel N`, схема extended-3)

Последовательная сетка мерит один промпт за раз. `--parallel N` добавляет второй
прогон: **N свежих промптов стартуют одновременно** (барьер). Размеры по умолчанию —
**32K, 64K, 128K, 250K** (то, о чём спрашивают параллельные батники p2/p3/p4).
Число раундов на каждый размер **интерактивно спрашивается при запуске** (рекомендуется
2; без флага `--parallel-runs` и без ответа — 2). Перед каждой длиной печатается
примерное **ETA раунда** из расчёта префилла 1500 tok/s (N × длина / 1500).

Метрики на длину (отдельная таблица в README):

- **Total prompt tok/s** — сумма prompt-токенов батча / wall-time: суммарная скорость
  префилла на всех слотах;
- **Per-stream prompt tok/s** — медиана по потокам; её падение против последовательной
  колонки выше = взаимное влияние слотов;
- **TTFT p50/p95** — очередь на слотах;
- **Slots busy** — сколько слотов движок одновременно считает занятыми: во время батча
  раз в секунду опрашивается `GET /slots` (`is_processing`, `n_prompt_tokens`) и в таблицу
  идёт пик одновременно обрабатываемых слотов. Это измеренное число, а не ожидание: если
  батч из N потоков показывает N — слоты работают, если меньше — часть потоков ждёт;
- **Scaling ×** — total / медиана последовательного прогона той же длины (1.0 = слоты
  не мешают друг другу, 2.0 на 2 слотах = идеальный масштаб).

Guard'ы:

- общий KV-пул: `N × (длина + 24 + 256) ≤ контекст`, иначе длина помечается `skipped`
  (например, на контексте 262144 два потока берут 64K, а 128K — нет);
- `N > parallel slots` — строка помечается «queued» (потоки в очереди), это не ошибка.

Пример (на батник p2):

```
python tools/strata_bench_extended.py --url http://127.0.0.1:8081 --api-key NoNeed --parallel 2
```

## Отличие от ориг. теста

- ориг. тест: фиксированные 4K/16K (+32K через `--long`) + chat + agent.
- расширенный: сетка 4K…250K, только prompt-замеры (chat/agent в расширенный не входят —
  они остаются в ориг. тесте). Метод, калибровка, теги и 24 ответных токена — общие.
